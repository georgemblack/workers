## Build

`scripts/build-client.mjs` uses esbuild (already a dev dependency) to bundle `src/client/main.tsx` (JSX via Preact: `jsx: "automatic"`, `jsxImportSource: "preact"`, minified, ES2022, IIFE) and reads `src/client/styles.css`, then writes `src/generated/client.ts`:

```ts
export const script = "…";
export const styles = "…";
```

Add `"jsx": "react-jsx"`, `"jsxImportSource": "preact"` and `src/**/*.tsx` to `tsconfig.json`.

`src/index.ts`:
- `GET /` → HTML shell: `<div id="app">`, `<link rel="stylesheet" href="/app.css">`, `<script src="/app.js" defer>`, viewport and `color-scheme` metas as in brain.
- `GET /app.js`, `GET /app.css` → the generated strings with correct content types and `Cache-Control: no-store`.
- CSP: `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`.
- Delete `src/temp-ui/` and `GET /api/chat`.

## Layout

```
Desktop (min-width: 900px)                    Mobile
┌───────────────┬──────────────────────────┐  ┌──────────────────┐
│ Chat (1/3)    │ [Tasks] [People]         │  │ active pane      │
│ messages ↕    │                          │  │ (scrolls)        │
│               │ dashboard ↕              │  │                  │
│ ┌───────────┐ │                          │  ├──────────────────┤
│ │ composer  │ │                          │  │ composer (chat)  │
│ └───────────┘ │                          │  │ [ Chat | Board ] │
└───────────────┴──────────────────────────┘  └──────────────────┘
```

- Desktop: CSS grid `grid-template-columns: 1fr 2fr`, height `100dvh`, a 1px `--line` divider. Each column scrolls on its own. Chat column: min width 320px, padding 24px. Dashboard column: content max width 760px, padding 40px 32px.
- Mobile: only the active pane is rendered. A two-segment control is fixed to the bottom (44px tall, respects `env(safe-area-inset-bottom)`), labels "Chat" and "Board". Pane padding 20px 16px, with bottom padding so content clears the bar. The active pane is saved in `localStorage` (`brain2-pane`); default "Board".
- Tabs: text buttons at the top of the dashboard pane from `state.tabs`; the active one has `--text` colour and a 2px underline, others `--muted`. Active tab saved in `localStorage` (`brain2-tab`).

## Style (carry over from brain)

- Variables: `--bg #fff / #191919`, `--text #262626 / #e5e5e5`, `--muted #737373 / #a3a3a3`, `--line #e5e5e5 / #353535` (light / dark via `prefers-color-scheme`). Font `15px/1.6 system-ui, sans-serif`; inputs 16px.
- Section heading: 19px, weight 600. Row: `padding: 10px 0`, bottom hairline. Sub-rows: 14px text, indented on a 1px guide line (`.item .items` in brain). Subtitle: 13px `--muted`.
- Priorities box: 1px border, 3px left border `#9b8157`, radius 8px.
- Chat: user text in a right-aligned bubble (`--line` background, radius 16px, max width 90%); replies plain with rendered Markdown (copy brain's `.markdown` rules); speaker and time lines 13px `--muted`.
- Buttons and the composer textarea: 1px `--line` border, radius 5px. Error text `#b95043`.
- Reference chip: inline pill, 13px, 1px `--line` border, radius 12px, with a small "×" button.
- Focus outlines as in brain. No icons, no shadows, no animation beyond the browser defaults.

## Components (`src/client/components/`)

- `App` — holds `state`, `pane`, `tab`, `detailId`, `refs`. Runs polling. Renders `Chat` and `Dashboard` (both on desktop; one on mobile).
- `Chat` — messages (auto-scroll to bottom when already near the bottom, as brain does), "Retry paused work" button when any message is `parked`, chips for `refs`, textarea, Send. Enter sends; Shift+Enter is a newline; ignore Enter during IME composition. A message with status `queued`/`running` shows "Working on it…"; `unanswered` shows "Could not finish: <detail>. Send a follow-up to try again."
- `Dashboard` — tabs, then `TasksView`, `PeopleView`, or `PersonDetail` when `detailId` is set.
- `TasksView` — "Priorities" box (if any), then one section per area with nested `Row`s. Empty: "Nothing on your list."
- `PeopleView` — filter input ("Find someone…"); sections "Catch up", "Birthdays", "Recent", then one section per circle with household sub-headings (13px `--muted`) and person rows. While the filter has text, show only a flat list of matching people (case-insensitive match on name, aliases and subtitle). Empty: "No one yet. Tell me about someone."
- `PersonDetail` — fetches `/api/nodes/:id`. "← People" link; name (19px, 600); `how_i_know` muted; `body`; "Family" (linked and backlinked people by relation, with household); "Ask about" (backlinked open follow-ups); "Facts" (bulleted); "Timeline" (date in muted 13px, then text); "Tasks" (backlinked non-closed tasks). Sections with no content are omitted. Refetch when `state.rev` changes.
- `Row` — title, subtitle, children.

## Behaviour

- **Polling**: `GET /api/state?rev=<current>`. Every 2s while any message is `queued` or `running`, otherwise every 10s; skip while `document.hidden`; poll immediately on `visibilitychange` to visible and after sending. On 204 do nothing.
- **Sending**: same as brain's `capture()`: generate a UUID, save `{ id, text, refs }` to `localStorage` (`brain2-pending`) before the request, clear on success, restore the draft on load, and reuse the same ID when the same text is retried. Body: `{ id, text, source: "chat", refs }`.
- **References**: clicking a task row or a follow-up adds `{ id, title }` to `refs` (max 5, no duplicates), focuses the composer, and on mobile switches to the chat pane. Clicking a person row sets `detailId`. While `PersonDetail` is open, that person is sent as a ref with every message unless removed with the chip's "×". Refs clear after a successful send (the open person's implicit ref stays).
- **Errors**: a failed request shows the message in an alert line at the top of the chat pane; it clears on the next success.
- All text from the server is rendered as text. Only `reply_html` is inserted as HTML (it is produced by the server's Markdown renderer, which must keep `html: false`).
